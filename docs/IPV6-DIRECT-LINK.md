# IPv6 直连邀请码与回执码

从 1.8.0-snapshot-3 起，BSK 邀请码和 ACK 回执码均固定为 **30 字符**：
4 个 ASCII 前缀字符（`BSK-` / `ACK-`）加 26 个汉字。汉字表使用
GB2312 一级的 3755 字，全部位于 Unicode 基本汉字区，不使用扩展区、
私用区、表情或特殊字体字符。目标 Windows 系统使用常规中文字体回退；
仍应复制原文，不要截图识别、转换简繁体或按字义修改。

## 双向确认与多人加入

1. 房主创建房间，把 BSK 原文通过可信聊天渠道发给好友。
2. 每位好友加入后生成自己独立的 ACK，通过同一可信渠道返回房主。
3. 房主逐个粘贴并放行 ACK，可以继续添加其他好友；重复相同 ACK 不重复建连接。
4. 新旧协议不兼容。所有参与者需更新后重新生成，旧码不能继续使用。

## 字段与边界

| 代码 | 38 字节载荷 |
| --- | --- |
| BSK | IPv6 16 字节 + 端口 2 字节 + 房间标识 4 字节 + 能力密钥 16 字节 |
| ACK | IPv6 16 字节 + 端口 2 字节 + 会话标识 8 字节 + HMAC 认证码 12 字节 |

另有 4 位复制校验，和载荷一起用定长 3755 进制编码。复制校验只辅助发现
误输入，不能检出所有错字，更不能代替身份认证。房间标识不是秘密。
能力密钥为每个房间随机生成的 128 位密钥，只经 BSK 分享，不放入 ACK
或 UDP 数据报。ACK 的 96 位 HMAC 绑定协议、房主当前房间、好友 IPv6、
端口和会话标识；重新计算复制校验不能伪造有效 ACK。

UDP 使用分方向派生的 HMAC-SHA256 密钥、完整 32 字节认证标签、
64 位计数器和 4096 包防重放窗口。未放行的端点不能凭数据包直接加入。
**游戏本身的载荷保持原样，不做额外加密**；这不是 TLS，也不提供内容保密。
汉字是编码，不是加密。掌握 BSK 的人掌握房间能力，不能抵御获邀成员
或已泄漏邀请码的冒用；泄漏时应重建房间。

## 验证范围

自动测试覆盖固定长度、最大载荷与前导零、常用字表、空白复制、非法输入、
ACK 字段篡改与错误房间、UDP 逐字节篡改、方向隔离、并发重放、
乱序与重传，以及房主加三名好友同时通过本机 IPv6 回环传输数据。
回环测试不等价于真实公网 IPv6 打洞或实际游戏联机验收。
