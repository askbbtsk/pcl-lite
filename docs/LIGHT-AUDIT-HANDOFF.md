# PCL Light 修复交接清单

核查基线：PCL Light `e35f2cd4`。本清单由用户提供的两份报告及对应源码核对整理；本轮优先修复、发布 PCL Lite，**未修改 Light，也未将源码核查表述为运行验收通过**。

## 1. 分段下载使用受限 Range 请求头

- 位置：`Core/Web.cs`，`TryRangeDownload` 与 `DownloadChunk`。
- 现状：直接赋值 `HttpWebRequest.Headers["Range"]`。在目标 .NET Framework 环境中这是受限头，会抛异常，使并行下载退回串行。
- 修复：探测和分段请求都使用该目标框架支持的 `AddRange`；检查 206、Content-Range 的区间及总长度，保留服务器不支持分段时的完整下载回退。
- 验收：支持 Range、不支持 Range、忽略 Range 返回 200、区间不符、取消、部分分段失败、最终哈希不符。必须在实际 net35 运行环境验证，不能只测新 .NET。

## 2. 旧版启动参数与 Windows 参数转义

- 位置：`Core/GameLauncher.cs`、`Core/VersionModel.cs`。
- 现状：旧版参数采用固定模板，未完整使用版本声明，缺少部分版本需要的 `userProperties`；引号处理直接翻倍反斜杠不符合 Windows 参数解析规则。
- 修复：按有效版本声明解析参数和占位符；兼容旧参数格式。按 Windows 引号/反斜杠规则转义每个参数，避免改变普通路径内容。
- 验收：1.7.10、1.12.2、1.16.5；离线/正版账号；含空格路径、尾部反斜杠、引号和空参数；检查实际子进程收到的参数。
- 不采纳“所有带空格路径必然失败”的过度结论。

## 3. 原生库选择、架构规则和提取

- 位置：`Core/VersionModel.cs`、`Core/GameDownloader.cs`。
- 现状：`${arch}` 未完整展开；平台规则未完整处理架构；普通 artifact 携带的 natives 也可能漏识别和提取。
- 修复：结合游戏 Java/原生库的实际架构解析规则和 classifier，区分 classpath 工件与需要提取的本地库，遵守提取排除项。
- 验收：x86/x64、允许与拒绝规则、`${arch}` classifier、普通 artifact 的本地库、排除项；不得把任意库都当作 native 解压。

## 4. 旧版资源映射

- 位置：`Core/GameDownloader.cs` 的资源索引读取与输出、启动时资源目录参数。
- 现状：读取 `map_to_resources`，未完整处理 `virtual`，旧版资源布局和启动资源根目录没有一致映射。
- 修复：分别处理普通对象存储、virtual 索引目录和实例 resources 目录；让启动参数指向对应版本实际使用的位置。
- 验收：使用真实旧版索引固定样本，核对逻辑资源路径、文件字节及启动目录；再进行声音、语言等游戏内检查。不能仅凭下载数量声称兼容。

## 5. 登录状态、刷新结果和 HTTP 错误

- 位置：`Core/MicrosoftAuth.cs`、`Core/AuthStore.cs`、`MainWindow.cs` 的启动与账号更新、`Core/Web.cs`。
- 现状：新刷新令牌已经保存到 AuthStore；但刷新成功后若后续启动失败，内存账号未必更新。离线回退会清空当前登录态；部分 HTTP 错误正文会按成功数据继续处理。
- 修复：账号刷新成功即同步有效内存状态；离线启动作为本次启动选择，保留正版账号以便后续重试。先检查 HTTP 状态，再解析成功响应；敏感令牌不得写入错误日志。
- 验收：刷新成功后启动失败、下一次启动、离线回退后恢复联网、无新 refresh_token、401/429/5xx 和非 JSON 错误正文。
- 不采纳“刷新结果完全没有保存”或“微软旧刷新令牌刷新后立即作废”的结论。

## 6. ZIP 边界校验和空搜索状态

- 位置：`Core/ZipMini.cs`、`MainWindow.cs` 的版本筛选与选择。
- 现状：中央目录文件名长度未在读取前完整校验；无效条目跳过后仍可能计入成功数。空搜索结果时显示可保留旧版本，而取值退回固定 `1.16.5`。
- 修复：每次读取前验证记录头、变长字段和数据范围，明确拒绝不支持的格式，成功计数仅计算实际提取结果。无有效选择时清空旧标签并禁用启动，不选择隐藏的默认版本。
- 验收：截断 ZIP、越界长度、空/无效条目、路径穿越、不支持压缩方式；搜索有结果→无结果→重新有结果，确认界面标签、实际选择和启动按钮一致。

## 交付要求

每项应有对应回归测试及适用 Windows/.NET Framework 的验证结果。保持下载取消、镜像回退、原文件保护和现有用户账号数据；不要把这些问题扩展成未经验证的整套架构重写。Lite 本轮发布不代表 Light 的上述问题已经修复。
