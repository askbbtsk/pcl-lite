# 单元测试并行策略

`PCL.Core.Test` 默认使用 MSTest 的类级并行，最多同时运行 4 个测试类。
同一个类中的测试仍按串行调度，保留测试初始化、清理和类内共享资源的边界。
本地 `dotnet test` 与 GitHub CI 使用同一程序集设置，无需单独开启。

以下涉及进程级资源的测试使用 `[DoNotParallelize]`，由 MSTest 独占调度：

- 修改全局配置、隐私开关、环境变量、事件总线和 Mixin 注册表。
- 清空全进程 SQLite 连接池。
- 依赖全局 WPF 资源或桌面捕获状态的已有测试。
- 使用进程总分配量断言流式打包内存上限的测试方法。

新测试应使用唯一临时目录、操作系统分配的端口和独立服务实例。
若必须修改进程级共享状态，应标注 `[DoNotParallelize]`，并恢复原状态；
不能依赖另一个测试先执行，也不能通过重跑来掩盖并发失败。
只读取仓库源码或随仓库分发的示例时，使用 `TestRepository.FindRoot()`，
不要假定测试输出目录位于源码目录下；构建产物可以独立放在 E 盘。
测试程序集在开始前显式初始化 WPF 的 pack URI 解析器，避免字体等测试
依赖其他测试先触发 WPF 启动；按过滤器单独运行也应得到相同结果。

需要临时禁用并行以定位问题时，可执行：

```powershell
dotnet test PCL.Core.Test/PCL.Core.Test.csproj -- MSTest.Parallelize.Workers=1
```

完整测试结果仍由 CI 输出 TRX；并行运行不会跳过失败用例，也不会绕过
发布工作流的完整 CI 成功条件。本地临时文件及构建产物应放到 E 盘。
