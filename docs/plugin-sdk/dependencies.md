# 插件依赖与加载顺序

插件清单可以声明必须同时安装并启用的插件依赖。宿主在执行任何插件 Mixin 前验证依赖、版本和依赖环，然后按依赖优先顺序应用 Mixin、调用生命周期。

```json
{
  "id": "example.addon",
  "version": "1.4.0",
  "dependencies": {
    "example.library": "^1.2.0"
  }
}
```

每个插件最多声明 64 个依赖。依赖 ID 使用清单的插件 ID 规则；不能自引用，ID 不区分大小写且不能重复。版本要求为 SemVer 2.0，范围最多 256 字符，支持：

- 精确版本：`1.2.3`
- 比较条件交集：`>=1.2.0 <2.0.0` 或 `>= 1.2.0, < 2.0.0`
- 插入符范围：`^1.2.3`；兼容上界按 SemVer major-zero 规则收窄
- 波浪范围：`~1.2.3`，即大于等于该版本且低于下一个 minor
- 任意 SemVer：`*`

当前管理器**不会自动下载或更新依赖**。作者应在测试和发布说明中清楚列出需要先安装的插件。缺失、禁用、版本不匹配、依赖环或依赖插件加载失败时，依赖它的插件会显示具体错误并跳过加载；其 Mixin 不会留下部分补丁。依赖插件先应用 Mixin、先执行 `StartAsync`，停止时按相反顺序释放。

禁用、卸载或更新依赖后重启启动器，依赖关系才会重新检查。插件依赖不是沙箱或权限边界；插件仍在同一个启动器进程和用户权限下运行。不要通过直接读取其他插件的私有数据目录来建立依赖协议。

## 验证

`PluginDependencyResolverTests` 覆盖 SemVer 范围、预发布版本、依赖拓扑、缺失/禁用/不匹配依赖以及环和下游阻断。`PluginPackageTests.RuntimeStartsCompiledPluginsInDependencyOrder` 通过真实签名包安装、加载两个编译程序集，确认依赖先启动后消费者启动。
