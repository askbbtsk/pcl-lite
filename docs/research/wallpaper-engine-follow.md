# Wallpaper Engine 壁纸背景

## 1.8.1-snapshot-1

在「个性化 → 自定义图片／视频背景」开启「跟随 Wallpaper Engine 壁纸」。
支持视频、Scene 场景和网页壁纸；清晰度为 25%–100%，默认 50%。

### 经用户确认调整的实现

直接获取 WE 桌面渲染子窗口未能取得独立画面。对照
[DSH 插件](https://github.com/elysia395/dsh-wallpaper-engine/blob/main/docs/HOW-IT-WORKS.md)
后，用户同意以效果和速度优先，不再要求桌面同帧同步。

采用 WE 官方 `openWallpaper -playInWindow` 创建启动器专属的独立渲染窗口，
再将该窗口画面交付给 Lite。视频、Scene、网页均交由 WE 自身渲染，
不内嵌另一套网页／场景引擎，也不复制壁纸素材。
独立窗口在屏幕外创建，移除边框和任务栏入口；仅关闭本启动器创建的窗口。

- 当前屏幕按启动器窗口覆盖面积选择，相同面积保留上次屏幕。
- 定期读取 WE 当前用户的壁纸分配，更换壁纸后重新加载。
- 关闭跟随、最小化或按原设置进入游戏暂停时停止采集并释放独立渲染窗口。
- WE 退出或壁纸不可用时恢复原背景，之后重试。
- 玻璃使用壁纸背景，暂停原桌面采样，不改写原桌面折射配置。
- 清晰度改变独立渲染窗口的分辨率，而不是仅缩放最终图片。

### 实机验证与限制

2026-11-16，WE 2.8.0.42 的 Scene 壁纸已验证独立窗口出图、无边框捕获授权、
采集和关闭清理。诊断样本的源帧年龄约 4–34ms，这不是端到端显示延迟。
视频、网页、多屏、不同系统及长时间运行仍需版本实测。

独立播放不保证与桌面进度、粒子随机状态或暂停时刻一致，会增加 WE 的资源用量。
不宣称达到原方案的小于 100ms 桌面同步门槛。未获无边框捕获授权或系统不支持时
显示不可用状态并恢复原背景；不降级为整屏捕获。

## 首版回归修复

首版只跑了采集原型，未覆盖完整的设置调用链，遗漏了两个可复现问题：

1. WE 在常规 argv 解码前读取 `RAW~(...)~END`。使用 `ArgumentList` 会转义 JSON
   的双引号，导致 `applyProperties` 返回退出码 4。现在仅该命令使用经校验的原始
   JSON 参数，不经过 shell；窗口名限制为本进程生成的格式，JSON 内的结束标记会转义。
2. 本机 WE 将负数坐标退回到 `(0,0)`，加上失败重试，会在左上角反复出现辅助窗口。
   创建位置改为正数屏幕外坐标，创建后先去边框／任务栏入口，再应用设置和开始采集。

位置和尺寸操作临时使用 PMv2 线程坐标，避免 125% 等 DPI 下的虚拟化尺寸偏差。
采集异常走延迟重试，不再每 750ms 重新创建窗口。

修复验证链接的是正式 `WallpaperEngineWindows`、`WallpaperEngineCapture` 和命令格式化代码，
不再使用另一份采集实现冒充完整集成验证。视频、Scene、网页分别取得 10 帧连续画面，
确认画面发生变化、640×360 物理尺寸及辅助窗口关闭；新增命令传输回归测试。

## 关闭玻璃后的白边

壁纸采集帧本身无白边。实机读取启动器的原生窗口区域，关闭玻璃后区域覆盖整个
`940×560` 窗口，包含尚未绘制背景的外侧边距；因此显示出约一圈窗口边距宽度的白色。

原生窗口裁剪现由统一刷新流程维护：玻璃或壁纸跟随任一正在使用时均保留，
并采用当前外观的圆角（普通 6、玻璃 22）。不放大或裁掉壁纸内容来掩盖窗口空白，
同时关闭两者后仍恢复原有窗口行为。裁剪测试覆盖两种圆角和四档 DPI。
