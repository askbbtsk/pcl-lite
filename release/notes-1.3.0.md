PCL Lite 1.3.0 正式版。

本说明汇总 **1.2 系列至 1.3.0 的全部更改**。1.2 线自 `1.2.1-beta` 起（未发布过 1.2.0），
至此共 7 个版本：`1.2.1-beta` / `1.2.2-beta` / `1.2.3-beta` / `1.2.4-beta` / `1.2.5-beta` /

## 新增

### Discord 状态显示（Rich Presence）　`1.2.1`

在 Discord 个人资料里展示你正在做什么，默认关闭，开关在 **设置 → 启动器 → Discord 状态显示**。

- **未开游戏**：显示启动器版本、内存占用、已运行时长
- **游戏运行中**：自动切换为实例名、游戏内存、游玩时长
- **时长由 Discord 自己跳动**，不会为了刷新计时器而反复上报
- **显示内容可多选**：启动器版本 / 启动器内存 / 游戏版本 / 游戏内存 / 游玩时长 / 服务器地址
- **服务器地址默认不显示**。它会从游戏日志里读当前连接的服务器，打开后任何能看到你资料的人
  都会知道你在哪个服，因此单独一项、默认关闭
- 应用 ID 已内置，打开开关即可用；也可以换成自己的 Discord 应用
- 状态只通过本机命名管道交给 Discord 客户端，**不经过任何第三方服务器**
- 支持「在 Discord 中清除」，可临时撤下状态

### 基岩版：从「能启动」到「下载 + 安装 + 启动」　`1.2.5` 起，`1.2.6` 成型

**1.2.5** 在百宝箱里加了「基岩版」页，能找出本机已装的基岩版并直接启动：

| 形态 | 怎么认 | 怎么启动 |
| --- | --- | --- |
| 商店版 | 系统包 `Microsoft.MinecraftUWP`（正式）/ `Microsoft.MinecraftWindowsBeta`（预览） | `shell:appsFolder\<包族名>!<AppId>` |
| GDK 便携版 | 解包目录里的 `Minecraft.Windows.exe` | 直接运行，不注册系统包，天然多版本共存 |

**1.2.6** 基岩版成为顶部导航的独立板块，就在「下载」右边，与启动、下载平级，分 **下载** 与
**启动** 两页，和 Java 版一样「在启动器里下载、在启动器里启动」：

- **下载**：版本列表来自 `data.mcappx.com`，微软商店已发布的基岩版全在里面（正式版 / 预览版 /
  Beta，共 500 多条），按版本号从新到旧排；支持按**发布通道**、**包形态**（UWP / GDK）筛选，
  也可以直接搜版本号；点右侧按钮即**下载 + 安装**一条龙，进度条与百分比实时显示，
  下载完自动校验官方 MD5
- **UWP（商店包）**：解压 → 删签名 → 改写清单（版本号 / TrustLevel / runFullTrust）→
  `Add-AppxPackage -Register` 注册进系统。可以装商店里已经没有的旧版本，多版本并存，
  商店更新也不会把它顶掉。需要开发者模式（旁加载），没开的话点「开发者模式」按钮可以一键尝试开启
- **GDK 包**：`.msixvc` 是加密的 XVC 容器，用内容密钥（CIK）解密后解包到启动器自己的目录，
  之后直接跑 `Minecraft.Windows.exe`，不注册系统包，多版本天然共存、甚至可以同时开
- **启动**：列出本机所有可启动的基岩版——商店里装的正式版与预览版、下载页解包出来的版本、
  以及手动添加的 GDK 目录（一级子目录也会扫）；启动、结束进程、打开程序目录、打开存档目录，
  都不需要管理员权限
- 下载的包与解包出来的版本都在启动器数据目录的 `Bedrock/` 下，删启动器时一起走

**1.3.0** 继续完善这一板块：

- **下载目录可以自己选**：GDK 解包后 2 GB 起，放系统盘容易撑爆，现在能换到别的盘
- **解包失败不留半成品**：中途取消、密钥不匹配或磁盘写满时，自动删掉解了一半的目录，
  不会留下一个点进去只报「损坏的映像」的残次品
- **启动列表会过滤残次品**：抽查根目录 DLL 头部，非 `MZ` 开头的解包目录不被列为可启动版本
- **左栏按钮与列表共享同一份状态**：解包进度每秒刷新几十次也不会把整个列表重画

### 基岩版 GDK 内容密钥（CIK）　`1.3.0`

- **正式版与预览版两把密钥均已内置**，安装 GDK 包不再需要手动填密钥或设环境变量
- 没有内置密钥（或密钥失效）时，安装前会**弹输入框让用户自己填**，填了才继续，
  避免「下载完 1 GB 才发现解不开」；用户填的值优先于内置值
- 解包前会先读取安装包内声明的 `EncryptionKeyIds`，与所用密钥的 GUID 比对，
  不匹配时直接给出明确错误，不会解出一堆乱码文件
- 密钥按**通道**分配、不按版本：正式版通道（1.21.120 ~ 26.52）共用一把，
  预览版通道（1.21.120.21 ~ 26.70.21）共用一把，一年来均未轮换
- 预览版密钥是商店分发的 DRM 内容密钥，**仅对持有正版 Minecraft 预览版的设备有效**；
  失效后仍可用环境变量 `PCL_BEDROCK_PREVIEW_CIK` / `PCL_BEDROCK_RELEASE_CIK` 覆盖
- UWP（商店包）的下载与安装始终不受密钥影响

## 安全：MCP 从「能用」到「敢开」　`1.2.5`

这一版把 MCP 的安全与协议层按审计报告逐条重做。以前最大的问题是：
**只要用户打开「允许修改启动器设置」，前面所有权限开关都会失效**——AI 可以自己把权限改回去。

### 权限与凭据

- **口令不可读**：`pcl_config_get` 读到 `McpToken` 直接拒绝，不再把明文送进对话记录
- **权限不可自我提权**：`Mcp*` 全部配置项与 `SystemDebug*` 一律不可写，只能由用户在界面上改
- **默认全关**：「允许修改游戏文件」「允许启动/停止游戏」默认值从 `true` 改为 `false`
- **比较不泄露时序**：口令比对改成 SHA-256 归一 + `FixedTimeEquals`
- **`?token=` 已移除**：查询串会整条进日志，等于把口令写进明文

### 启动参数白名单

`extraArgs` 原来原样拼进 Java 命令行，等于给了一条代码注入通道。现在：

- 拒绝 `-javaagent:` / `-agentlib:` / `-agentpath:` / `-Xbootclasspath` / `-Djava.system.class.loader` 等
- 拒绝 `-jar` / `-cp` / `--module-path` 这类改变启动目标的参数
- 拒绝含空白与引号的参数（最终用空格拼接，带空格会被拆错）
- 上限 32 个、单个 512 字符

### 协议层

- **取消是真的**：`notifications/cancelled` 会中断在飞请求，另有 3 分钟请求超时，超时返回 `-32800`
- **错误语义不再混用**：未知工具 / 资源 / 提示词返回 `-32602`，不再返回「空结果」
- **500 不再回堆栈**：只回通用文案，详情进日志
- **结构化输出**：`tools/call` 同时返回 `content` 与 `structuredContent`
- **并发与体积上限**：4 并发（超出 `503`）、请求体 4 MB（超出 `413`）
- **同时绑 v4 与 v6 回环**：客户端把 `localhost` 解析成 `::1` 时也能连
- **UI 线程不再挂死**：需要界面的工具有 20 秒上限，超时返回明确错误

### 路径沙箱

`ResolveUnder` 现在会把路径逐级展开 junction / 符号链接再比前缀。以前只做字符串前缀比较，
游戏目录里放一个指向 `C:\` 的目录联接就能越界。

### 审计日志

变更类工具（写 / 启动控制 / 配置）会往 `PCL/Log/mcp-audit.log` 记一行 JSON：
谁、什么时候、调了什么、参数摘要、成功与否。读取类不记，口令类键名不进日志。

## 修复

### 更新下载完却报「SHA256 不正确」，新版本装不上　`1.2.4`

下载跑完 100% 之后弹「校验更新失败：更新文件 SHA256 不正确，应该为 ，实际为 502d5490…」——
注意「应该为」后面是**空的**。GitHub 更新源拿不到官方哈希时把 `Sha256` 设成空字符串表示「不校验」，
可下载完的校验环节是**无条件**比对的，空字符串和任何真实哈希都不相等，所以这条校验必然失败。
1.1.0 以来所有通过 GitHub 源更新的尝试都会撞上这个。

现在：没有官方哈希就跳过校验；能拿到时真的校验（GitHub Release 附带的 `digest` 字段，
只认 `.exe` 附件）；比对忽略大小写。

> **升级提醒**：1.2.3 及更早的版本装不上这个更新（bug 就在它们身上），
> 需要手动下载一次本版安装包，之后自动更新就正常了。

### 打开设置页直接崩溃　`1.2.2`

1.2.1-beta 打开「设置」会报 `XamlParseException: 无法从文本"BtnDiscordPortal_Click"创建"Click"`，
整个设置页加载失败。原因是 Discord 那三个按钮的事件处理函数签名写成了 `(object, EventArgs)`，
而 `MyButton.Click` 用的是自定义委托 `(object, MouseButtonEventArgs)`——这种不匹配**编译期查不出来**
（事件挂接走运行期 `Delegate.CreateDelegate`），只有真正打开页面才会炸。

### 切到 Beta 通道后查不到新版本　`1.2.2`

启动器开着的时候发布了新版本，之后点多少次「重新检查」都显示「已是最新版本」——版本列表在启动时
拉一次就缓存到进程结束。现在：「重新检查」和切换通道会**强制重新拉取**；自动检查的缓存有效期改为
5 分钟；切换通道时先写配置再检查（原来是反过来的，用的还是旧通道的结论）。

### Dev 通道被当成正式版　`1.2.2`

选「Dev」时 `IsCurrentVersionBeta` 只认 `== 1`，把 Dev（2）当成正式版，导致选了 Dev 反而收不到
任何预发布版本。

### Atom 降级通道把 beta 当正式版　`1.2.2`

GitHub API 被限流时会降级用 `releases.atom`，而 Atom 不提供 prerelease 标记，原来一律按正式版处理。
现在按 tag 里的 `-` 后缀判断。

### Discord 状态「已连接」但看不到　`1.2.2`

Discord 同一时间只显示一个「正在玩」，别的 RPC 应用会抢走这个位置；而原来内容没变就不再上报，
一旦被抢走就再也回不来。现在**每 30 秒重发一次**，被抢走后最多 30 秒能抢回来，
`activity` 也显式带上 `type: 0`。

### 基岩版版本列表排序在运行期抛异常　`1.2.6`

`BedrockVersionCatalog.SortKey` 返回 `List<int>` 而不是可比较的值，排序时直接炸。

### Java 版本分析器的两个真 bug　`1.2.5`

- `RecommendedJavaMajor("1.21")` 原来返回 17（应为 21）——判断写成了 `minor >= 20 && patch >= 5`
- `ParseJavaMajorFromPath("…jre1.8.0_51…")` 原来返回 0，导致「Java 版本过低」检查整段被跳过

## 移除

### EasyTier 联机功能　`1.3.0`

联机功能整体删除，一个入口都不剩：

- **模块**：EasyTier 组网、大厅（Lobby）、房间码协议（Scaffolding）、Natayark 账号服务全部移除
- **入口**：工具页的「联机」分类与设置页的「联机」子页删除，工具页现在只有「百宝箱」一栏
- **设置**：个性化设置里的「联机」「大厅」隐藏开关、联机根服务器、Natayark OAuth 凭据一并清理
- **语言**：四套语言的联机文案共 716 条全部移除
- 网络用途登记表里的 EasyTier 中继节点、大厅账号条目同步移除
- 设置页「停止使用 PCL Lite」的说明里移除了已不存在的 Natayark 账户条目

删除是彻底的：没有残留代码、没有残留配置项、没有残留资源键，编译零错误。

### 其它移除

- 原「百宝箱 → 基岩版」入口移除，功能整体搬到顶部导航的独立板块　`1.2.6`
- 更新后的「PCL Lite 版本说明」弹窗移除　`1.2.6`

## 已知问题

- UWP 安装需要开发者模式；系统策略禁用旁加载时只能手动到「设置 → 系统 → 开发者选项」打开
- 预览版 GDK 包仅在设备拥有该包 license（装过商店预览版）时才能解密
- 下载源为社区维护的商店版本索引，接口变动时列表可能拉不到，界面会给出明确提示
- Discord 状态需要 Discord **桌面端**在运行，网页版不行；若本机同时有别的程序在发
  Rich Presence，两边会来回抢「正在玩」的位置
- 发布文件已做代码签名（SHA-256 + DigiCert 时间戳）；证书为自签名，暂无商业信誉，
  个别安全软件首次运行时仍可能提示发布者信息
- 自动更新暂不做完整性哈希校验，以下载通道自身的安全性为准
