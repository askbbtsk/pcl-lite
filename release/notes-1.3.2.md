PCL Lite 1.3.2 正式版。

## 修复：更新装完，版本号还是旧的

从 1.3.1 升上来会出现一个死循环：检查更新说有新版本 → 下载、替换、重启 →
回来仍然自报 **1.3.1** → 又说有新版本。文件其实已经换成新版了，只是程序自己不知道。

原因是版本号有两个真源：`csproj` 里的 `AssemblyVersion` 和 `metadata.json` 里的 `version`。
发版时只改了前者，后者还停在 1.3.1，而启动器显示与比较版本用的是**后者**。

现在 `metadata.json` 是唯一真源，两个 csproj 在构建时从它读版本号，csproj 里不再手写。
两个真源就一定会有一边被漏掉，这类问题不该靠「下次记得」来避免。

## 更新通道改版

原来的「正式版 / 测试版 / 开发版」换成三档，**每一档都是包含式的**：

| 通道 | 收哪些版本 |
| --- | --- |
| **预览体验** | 正式版 + 预览版（`pre`） |
| **快照尝鲜** | 正式版 + 预览版 + 快照版（`snapshot`） |
| **始终最新** | 正式版 + 预览版 + 快照版 + 不稳定版（`nightly`） |

版本后缀的四种取值：

| suffix | 版本名示例 | 叫法 |
| --- | --- | --- |
| （空） | `1.3.2` | 正式版 |
| `pre` | `1.3.3-pre` | 预览版 |
| `snapshot` | `1.3.3-snapshot` | 快照版 |
| `nightly` | `1.3.3-nightly` | 不稳定版 |

`beta` / `alpha` / `rc` 都归到预览级。

**为什么要「包含式」**：如果「始终最新」只收 nightly，用户拿到 `1.3.2-nightly` 之后，
正式版 `1.3.2` 发布时按版本号本来就该升上去（`1.3.2 > 1.3.2-nightly`），
但只要通道把正式版过滤掉，这条路就断了，用户会一直卡在 nightly 上等下一个 nightly。
反方向同理：从激进通道切回保守通道，手里的版本比保守通道的最新版还新时，
会直接判为「已是最新」，不会提示你降级。

老配置不需要迁移：三个选项的数值与原来的正式版 / 测试版 / 开发版一一对应。

## QQ 交流群改用官方短链

1.3.1 点群号走的是 `mqqapi://` 协议，实际有三个问题：只弹群名片、还得自己再点「申请加群」；
没装 QQ 或系统清理过协议关联时点下去毫无反应；部分系统会拦截未知协议。

现在改成 QQ 官方加群短链，**用默认浏览器打开**：

```
https://qm.qq.com/q/BmreYx71rq
```

手机上会直接唤起 QQ 落到加群界面，桌面上展示群信息与「加入群聊」按钮。
不依赖本机协议注册。浏览器都起不来时仍退化为复制群号。

入口不变：**欢迎页的「社区」卡片**，以及 **设置 → 关于 → 贡献者列表下方**。

## 已知问题

- 发布文件已做代码签名（SHA-256 + DigiCert 时间戳）；证书为自签名，暂无商业信誉，
  个别安全软件首次运行时仍可能提示发布者信息
- 自动更新暂不做完整性哈希校验，以下载通道自身的安全性为准
- 主页语言信封与 `lang:` 标签是 PCL Lite 扩展，原版 PCL 加载含这些内容的文件时
  会按普通 XAML 渲染（所有语言分支堆在一起）——属于预期的单向兼容
- UWP 安装需要开发者模式；系统策略禁用旁加载时只能手动到「设置 → 系统 → 开发者选项」打开
