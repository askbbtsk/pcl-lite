PCL Lite 1.3.3 正式版。

## 自动更新：改成一个开关，默认关闭

以前是「自动下载并提示 / 仅提示 / 关闭」三选一的下拉，默认还是自动下载。
现在换成一个复选框，**默认不勾**：

- **不勾**：启动时完全不联网，只有你自己点「检查更新」才会去查
- **勾上**：按下面的「更新方式」执行（自动下载并提示 / 仅提示）

不勾时「更新方式」下拉会置灰，因为那个选项没有意义了。

默认关掉是有意的：装完就自己联网、还可能在用户没同意的时候替换掉自己的 exe，
这不该是默认行为。想省事的话勾一下就行。

## 更新通道：补回「稳定版」

上一版只有三档，把「只收正式版」这一档弄丢了。现在补齐为四档，
**每一档都包含上面所有更稳定的版本**：

| 通道 | 收哪些版本 |
| --- | --- |
| **稳定版**（默认） | 只收正式版，一条预发布都不收 |
| **预览体验** | 正式版 + 预览版（`pre`） |
| **快照尝鲜** | 正式版 + 预览版 + 快照版（`snapshot`） |
| **始终最新** | 正式版 + 预览版 + 快照版 + 不稳定版（`nightly`） |

版本后缀的四种取值：

| suffix | 版本名示例 | 叫法 |
| --- | --- | --- |
| （空） | `1.3.3` | 正式版 |
| `pre` | `1.3.4-pre` | 预览版 |
| `snapshot` | `1.3.4-snapshot` | 快照版 |
| `nightly` | `1.3.4-nightly` | 不稳定版 |

`beta` / `alpha` / `rc` 都归到预览级。

**为什么要「包含式」**：如果「始终最新」只收 nightly，用户拿到 `1.3.3-nightly` 之后，
正式版 `1.3.3` 发布时按版本号本来就该升上去，但只要通道把正式版过滤掉，这条路就断了，
用户会一直卡在 nightly 上等下一个 nightly。反方向同理：从激进通道切回保守通道，
手里的版本比保守通道最新版还新时会直接判为「已是最新」，不会提示降级。

老配置不需要迁移：`Release` 落在稳定版、`Beta` 落在预览体验。

## 上一版修的那个更新死循环

1.3.2 修掉了「更新装完仍显示旧版本号」的问题（版本号有两个真源，
发版时只改了一处）。如果你是从 1.3.1 或更早升上来的，这一次更新会一次到位；
之前那种「说有新版本 → 重启还是旧的」的循环不会再出现。

## 已知问题

- 发布文件已做代码签名（SHA-256 + DigiCert 时间戳）；证书为自签名，暂无商业信誉，
  个别安全软件首次运行时仍可能提示发布者信息
- 自动更新暂不做完整性哈希校验，以下载通道自身的安全性为准
- 主页语言信封与 `lang:` 标签是 PCL Lite 扩展，原版 PCL 加载含这些内容的文件时
  会按普通 XAML 渲染（所有语言分支堆在一起）——属于预期的单向兼容
- UWP 安装需要开发者模式；系统策略禁用旁加载时只能手动到「设置 → 系统 → 开发者选项」打开
