PCL Lite 1.3.4 正式版。

## 这个版本只修一件事

**1.3.3 的正版登录是坏的。** 打包时漏掉了微软 OAuth 的 Client ID 注入，程序里那个值是空的，
点「微软登录」会直接提示未配置 Client ID。

1.3.4 重新带密钥编译，正版登录恢复正常。功能上与 1.3.3 没有任何区别——
如果你不用正版登录，留在 1.3.3 也没有影响，但建议还是升上来。

## 1.3.3 带来的改动（没变）

### 自动更新：改成一个开关，默认关闭

- **不勾**（默认）：启动时完全不联网，只有你自己点「检查更新」才会去查
- **勾上**：按下面的「更新方式」执行（自动下载并提示 / 仅提示）

不勾时「更新方式」下拉会置灰。默认关掉是有意的：装完就自己联网、
还可能在用户没同意的时候替换掉自己的 exe，这不该是默认行为。

### 更新通道：四档，都是包含式

| 通道 | 收哪些版本 |
| --- | --- |
| **稳定版**（默认） | 只收正式版，一条预发布都不收 |
| **预览体验** | 正式版 + 预览版（`pre`） |
| **快照尝鲜** | 正式版 + 预览版 + 快照版（`snapshot`） |
| **始终最新** | 正式版 + 预览版 + 快照版 + 不稳定版（`nightly`） |

每一档都包含上面所有更稳定的版本。这样「始终最新」的用户拿到 `1.3.4-nightly` 之后，
正式版 `1.3.4` 发布时仍然能正常升上去，不会因为版本号更大而卡死。

## 从 1.3.3 升上来的话

自动更新开关是新增的配置项，默认关闭。也就是说**升级后不会自动检查更新**，
想让它自动查就手动勾一下。

## 已知问题

- 发布文件已做代码签名（SHA-256 + DigiCert 时间戳）；证书为自签名，暂无商业信誉，
  个别安全软件首次运行时仍可能提示发布者信息
- 基岩版 GDK 安装包（`.msixvc`）解包依赖内置的内容密钥（CIK），正式版与预览版各一把，
  均已编入本构建；密钥若被官方轮换会失效，届时用环境变量覆盖即可，不必重新下载启动器
- 主页语言信封与 `lang:` 标签是 PCL Lite 扩展，原版 PCL 加载含这些内容的文件时
  会按普通 XAML 渲染（所有语言分支堆在一起）——属于预期的单向兼容
- UWP 安装需要开发者模式；系统策略禁用旁加载时只能手动到「设置 → 系统 → 开发者选项」打开
