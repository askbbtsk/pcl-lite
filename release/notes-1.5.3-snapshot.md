## ① 双击 PCL 却什么都没发生

有人反馈双击 PCL 之后进程直接没了，`Log/LastPending.log` 里只有两句：

```
[单例|single-instance] 发现重复实例 51864，尝试传递参数并拉起主窗口
[生命周期|lifecycle] 单例 已请求退出程序
```

这确实是「已经有一个 PCL 在跑」，但处理方式太糙了 —— 原来的逻辑是
**只要锁被占着就退出**，不管有没有真的把请求送到、也不管对面还活着没：

- **锁是陈旧的**（上次进程没走正常退出，或者文件被杀软 / 资源管理器预览占着）→
  照样判定重复，照样退出，PCL 就再也打不开了
- **对面还在启动中**（RPC 管道要到 `Loaded` 状态才建起来）→ 一次连不上就放弃
- **转交失败也不吭声** → 用户看到的现象就是「双击了，没反应，也没报错」

现在改成：

1. 先读锁里的 PID，**确认这个进程还活着**。已经不在了就接管锁继续启动
2. 活着就转交请求，**最多重试 6 次、每次间隔 500ms**，等对面把管道拉起来
3. 重试完还是不行，**弹窗告诉你**「PCL 已在运行（进程 xxx），但没能唤醒它的窗口」，
   并说明可以到任务管理器结束它
4. 转交成功按正常退出处理（退出码 0），不再当成错误

顺手修了一个会带崩主进程的空引用：`REQ activate` 处理里 `app.MainWindow!`
直接解引用，主窗口已经关掉、进程还在的情况下会抛 NRE。
（顺带一提，锁文件的删除现在会先核对里面记的是不是自己的 PID，
避免把接管者的锁一起删掉，反而放出两个实例。）

## ② Lunar 不必先去官方启动器登录了

以前如果本机 Lunar 账户库是空的（典型情况：装了但从没登录过，或者干脆没装），
PCL 会去找「主页面登录凭据」，而那份凭据只有真正启动过一次游戏之后才有值 ——
于是走一遍完整的微软登录加载器，多弹一次浏览器，用户以为出问题了。

现在直接读 PCL Lite 的账号列表：**只要在 PCL 里登录过微软账号，就能启动 Lunar**。
账户库为空时会按这个账号自动建一份 `accounts.json`（已有账号一律不动），
游戏内的身份也就对上了。

```
账号优先顺序：
 ① 下拉框里手选的 PCL 账号
 ② 下拉框里手选的 Lunar 账号（会把 Lunar 激活账号一起切过去）
 ③ PCL Lite 当前登录的微软账号   ← 以前这里是「主页面登录加载器」
 ④ 兜底再走一次主页面登录
```

## ③ Lunar 启动页的说明文字改对了

上一版把安装整段搬进了 PCL，但页面上的「说明」还写着
**「前置条件：本机已安装 Lunar Client 并至少启动过一次」** ——
这条已经不成立了，现在物料全由 PCL 自己下。相关几段一起改了：

- 删掉「前置条件：本机已安装并启动过」
- 账号那段改成「优先用 PCL Lite 已登录的账号，不需要先在 Lunar 启动器登录过」
- 状态行从「未安装 Lunar Client」改成「还没有下载 Lunar 物料」，
  并写明不需要装官方启动器
- 账号下拉框的悬浮提示同步更新

## 已知问题

- 发布文件已做代码签名（SHA-256 + DigiCert 时间戳）；证书为自签名，暂无商业信誉，
  个别安全软件首次运行时仍可能提示发布者信息
- 基岩版 GDK 安装包（`.msixvc`）解包依赖内置的内容密钥（CIK），正式版与预览版各一把，
  均已编入本构建；密钥若被官方轮换会失效，届时用环境变量覆盖即可，不必重新下载启动器
- Lunar 的本地 IPC 只实现了 `AuthService/RefreshAccount`（会话续期），
  好友列表、游戏内商店、聊天面板这些走 IPC 的功能仍然是空的。回空响应是安全的，
  游戏不会崩，只是对应界面没数据。
- 首次安装会下 300～500 MB（取决于版本），网速慢的话请耐心等进度条。
- 主页语言信封与 `lang:` 标签是 PCL Lite 扩展，原版 PCL 加载含这些内容的文件时
  会按普通 XAML 渲染（所有语言分支堆在一起）——属于预期的单向兼容
- UWP 安装需要开发者模式；系统策略禁用旁加载时只能手动到「设置 → 系统 → 开发者选项」打开
