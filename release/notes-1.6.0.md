PCL Lite 1.6.0 正式版。

从 1.5.1 到这一版中间隔了 11 个快照 / 预览版，这里一次性写全。

## ① Lunar Client 不用再装官方启动器了

以前 PCL 启动 Lunar 有个隐含前提：**本机已经装过 Lunar 官方启动器**，物料缺了只会甩一句
「请先用 Lunar 启动器跑一次这个版本」。现在官方启动器准备物料的 7 个阶段全部由 PCL 自己跑，
顺序照抄：`licenses → textures → assets → artifacts(+natives) → jre → ui → logs`。
`~/.lunarclient` 是空的也能一路装完——实测全新目录装 1.8.9 用 **478 MB / 约 4 分 45 秒**，
第二次启动 **6 秒**（文件都在，全部命中哈希）。装过官方启动器的机器目录结构一致，直接复用。

**每个版本可以自己选 loader。** 服务端的 `modules` 清单说这个版本能装什么，就按它来：

| module | 显示名 |
| --- | --- |
| `lunar` | Lunar + OptiFine |
| `lunar-noOF` | Lunar |
| `fabric` | Lunar + Fabric |
| `forge` | Lunar + Forge（老版本才有） |

版本下拉框下面多了一行胶囊按钮，点一下就换。默认跟着官方走（1.17.1 默认 Fabric，
1.8.9 默认 OptiFine）；切到不提供该 loader 的版本会自动退回该版本的默认，
但**你的选择不会被覆盖**，切回去还在。换 loader 只换附件清单，主类和 JRE 不变，不用重下 JRE。

**启动目录固定用 MC 根目录**（`.minecraft`），不再跟着主页面上选中的实例走。
以前选着一个 Fabric 模组包去开 Lunar，会把低版本客户端写进那个模组包的隔离目录，
`options.txt`、存档、资源包全被搅乱。现在存档和平时玩的是同一份。

**缺的原版客户端改由 PCL 下载。** Lunar 首次启动某版本时，`Genesis` 会先把整个原版客户端补到
`%APPDATA%\.minecraft`（jar + json + `libraries` 几百个文件 + 资源索引，约 100–200 MB，
实测能到 1321 MB / 970 个文件），**全程不开窗口、不打印进度**——从外面看就是「点了启动没反应」。
现在启动前用 PCL 自己的库文件清单逐个核对，缺一个就算没就绪，交给 PCL 的下载任务，
**进度进下载任务栏、能暂停**。补不齐也不拦启动，Genesis 会再试一次。

顺带把代理注入 JVM 了：`Genesis` 的下载用 Java `HttpClient`，**不读系统代理**，直连被墙时
主线程会永久阻塞在 `send()`。现在 PCL 当前生效的代理会翻成 `-Dhttp(s).proxyHost` 塞进参数，
没配代理时退回 `-Djava.net.useSystemProxies=true`，`127.0.0.1` 已在 `nonProxyHosts` 里放过。

物料目录和启动目录现在都能自己指定（C 盘紧张或者想隔离一套存档），右边各有两个小按钮：
「选目录」立刻生效、「恢复默认」一键回去。物料目录下面挂着物料、JRE 和账户库，换它等于换一整套环境。

## ② 会话过期不用再开一次 Lunar 启动器

以前每次 Lunar 会话过期（24 小时一次），游戏内账号面板就变成
**Invalid session. Please re-authenticate.**，唯一解法是打开一次官方启动器。

游戏进程里的 `lunar.jar` 在令牌过期时会通过本地 WebSocket（`ws://127.0.0.1:<--ipcPort>`）
调 `AuthService/RefreshAccount` 找启动器要续期。现在由 PCL 自己当这个服务端：

- 启动前抢 `28190`。抢到了就把 `--ipcPort 28190` 传给游戏，由 PCL 应答续期
- 抢不到说明官方启动器正开着，端口原样交给游戏，不会两个服务端抢同一条连接
- 但**只要 PCL 能自己续期**，就不让位——退到 `28191` 自己接。官方启动器开着却没登录时
  它根本续不了，让位等于白白丢掉续期能力
- 端口被占且对方不响应 WebSocket，就传 `--ipcPort 0`，干脆不启用

续期用的是 **PCL 自己登录**的微软账号（Lunar 的 `refreshToken` 绑在它自己的 OAuth 应用上，
拿它换新令牌只会得到 `AADSTS70000`）。而且**令牌过期不等于没登录**：以前
`if (AccessToken 为空 || IsExpired) return null` 直接把过期的判成「没有这个账号的登录」，
现在会先用档案里的 refreshToken 静默刷一次（不弹窗、不重登），新令牌写回
`accounts.json` 再启动。刷不动时页面会写清原因，并提示游戏内仍会显示 Invalid session。

**选了 PCL 账号 A、进游戏却是 Lunar 账号 B** 的问题也修了。游戏进程**不读**命令行里的
`--accessToken`，只认 `accounts.json` 的 `activeAccountLocalId`；以前找不到同 UUID 的账号
就只写一行日志照旧启动，于是激活账号还指着 B。现在会把 A 按 PCL 的登录补一条写进账户库再切过去，
只动 A 自己那一条（写前留 `accounts.json.pclbak`，写入走临时文件 + 换名）。

## ③ 更新链路：多源清单，点更新不再卡死

**先说卡死。** 设置 → 启动器 → 更新 页里，只要进来时正好有更新在下载，整个窗口就再也画不动，
连「取消」都点不了。原因是那段刷新进度的代码是个跑在 UI 线程上的忙等循环：

```csharp
while (Loading) { RunInUi(...); Thread.Sleep(200); }
```

UI 线程不泵消息，动画线程的 `RunInUiWait` 也跟着一起堵死。现在换成 `DispatcherTimer`
每 200ms 回一次 UI 线程刷文案，期间界面照常响应。

**再说多源。** 原来更新清单只有一个仓库指针，那个仓库整体出事（组织被标记、账号被暂停、
Release 被删）时客户端没有任何退路——2026-10 就这么断过一次。现在多了一份
`updatev2.json`，一次列多个仓库，每个带权重：

```json
{
  "schema": 2,
  "sources": [
    { "repo": "askbbtsk/pcl-lite", "tier": "official" },
    { "repo": "some-mirror/pcl-lite", "tier": "mirror" }
  ]
}
```

**选优规则是权重分档，不是版本最新**：源按权重分档、从最高档开始问，
**最高档只要有一个源把版本报回来了就当场定下来，低权重档连请求都不发**。
只有同一档内部（权重相等，本来就是同一个项目的几个镜像）才比版本号。
低权重不是「并列候选」，是「高权重全挂了才轮到」的替补。

为什么不让版本最高的赢：权重是发布者亲手写在清单里的，版本号是远端仓库说了算的。
反过来的话，清单里只要混进一个别的项目（粘错仓库，或者某个仓库被接管后发了个 2.x 的假包），
它会因为版本号更高直接赢，客户端就去下载并执行别人的 exe 了。

**身份校验看 `tier`，不看权重。** `official` 免校验、零额外请求（校验要走 raw / jsDelivr，
被墙时会把官方源判死，用户就彻底收不到更新了）；其余任何 tier 都要拉该仓库根目录的
`update.json`，能解析成合法指针才用。所以**任何一个仓库要被当作镜像列进清单，
根目录就必须有一份 `update.json`**。

老客户端只认 `update.json`，那份文件原样留着；新客户端先试 v2，404 / 写坏 / 超时都静默退回
单指针，两条路都断才算这次检查更新失败。

## ④ 「转移 PCL 设置」终于转得了

之前的导入是「把源文件复制到目标位置」，看起来天经地义，实际一点用都没有：配置在程序启动时
就被整份读进内存，`Sync()` 时又整份重写文件。运行中复制过去的配置，**十几秒后就被内存里的
旧值盖回去**。证据很直接：源文件 10834 字节，目标文件只有 2541 字节，旁边还留着导入时生成的
`.importbak`——导入执行过，内容没了。

现在导入只写 `*.pending` 暂存文件，下次启动时**在配置读入内存之前**换上去（原文件先备份成
`.importbak`），换完**自动重启**。正版账号也一起过来：账号存在配置的 `Profile` 项里且是加密的，
所以 `UserKey.bin` 会跟着迁——只拷配置不拷密钥，得到的只是一串解不开的密文。

认三种来源：

| 来源 | 认的标志 | 怎么导入 |
| --- | --- | --- |
| PCL CE / PCL Lite | `config.v1.json` | 连 `UserKey.bin` 一起复制 |
| PCL2 原版 | `setup.ini` | 逐行转成本地配置 |
| PCL2 便携版 | `PCL\setup.ini` | 同上 |

**PCL2 存在注册表里的那 58 项也一起搬。** PCL2 的配置其实分两半：`PCL\setup.ini` 是明文默认项，
通常只有十几个；`HKCU\Software\PCL` 里有 83 个显式标了注册表来源的键，其中 19 个加密。
也就是说代理设置、调试开关、启动次数这些**从来没被搬过来过**。现在两半都读，83 个里能对上
58 个。加密的 19 个用 `EncryptHelper.SecretDecrypt` 解，密钥派生自 `SHA256(CpuId)`，
**换台机器就解不开**——那种情况跳过该键并记日志，不会写空值。

导入本身也做扎实了：**只写 PCL Lite 真认得的键**（`setup.ini` 里混着一堆早就没有的键，
原样塞进去只会把配置弄脏，一个都认不出来时直接报错而不是假装成功）；**先合并再覆盖**
（以前是凭空造一份新的盖过去，你在 PCL Lite 里已经调过的东西会一起没了）；
自动扫描也覆盖 MC 根目录（PCL2 大多是便携版，启动器一般就扔在 `.minecraft` 那一层）。
导入前有二次确认，覆盖前留 `.importbak`，**源文件夹只读**。

## ⑥ 双击 PCL 却什么都没发生

原来的单例锁逻辑是**只要锁被占着就退出**，不管有没有真的把请求送到、也不管对面还活着没：

- 锁是陈旧的（上次进程没走正常退出，或者文件被杀软占着）→ 照样判定重复、照样退出，PCL 再也打不开
- 对面还在启动中（RPC 管道要到 `Loaded` 才建起来）→ 一次连不上就放弃
- 转交失败也不吭声 → 用户看到的就是「双击了，没反应，也没报错」

现在先读锁里的 PID **确认进程还活着**，不在了就接管锁继续启动；活着就转交请求，
**最多重试 6 次、每次 500ms**；还是不行就**弹窗**说明「PCL 已在运行（进程 xxx），
但没能唤醒它的窗口」。删锁前也会先核对文件里记的是不是自己的 PID，避免把接管者的锁一起删掉、
反而放出两个实例。

## ⑦ 不再向任何服务器上报版本号

「设置 → 关于」里原本写着「本软件的 User Agent 中包含启动器的版本号，以统计各版本的用户数量」。
这句话不是免责声明，它描述的是一件真事。这次把三处上报点全部掐掉：

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| `HttpSenderExtension`（通用请求） | `PCL-Lite/1.5.10-pre` | `PCL-Lite` |
| `NetworkService`（HttpClient 默认头） | `PCL-Lite/1.5.10-pre` | `PCL-Lite` |
| `RequestSigning`（下载器 UA） | `PCL2/2.12.1.0 PCLCE/1.5.10` | `PCL2 PCLCE` |

顺带删掉一处更隐蔽的：通用请求原来还带 `Referer: https://<构建号>.ce.open.pcl2.server/`，
构建号直接写进了域名。**除此之外网络行为一个字都没动**——没有新增请求，没有新增字段，
也没有关掉任何已有功能。

「关于」页里那段已经变成假话的说明（含「隐私说明」小标题）和早就没人维护的
「用户协议与免责声明」按钮一起删了；「开源与法律信息」卡片里仍然保留 README 和
「查看开源代码」两个入口。

> 1.5.11 改 UA 时踩了个坑：`new ProductInfoHeaderValue("PCL-Lite")` 的单参数重载收的是**注释**
> 而不是产品名，构造时直接抛 `FormatException`，而这行在 `ConfigureHttpClient` 里，
> 等于任何一次网络请求都会炸——下载页、模组搜索、CurseForge 和 Modrinth 全部取不到数据。
> 1.5.12 已修（双参数、显式传 `null`，下载器那行也换成 `TryAddWithoutValidation`）。
> 1.6.0 不含该问题。

## ⑧ 界面与体验

- **窗口大小可以设了**：设置 → 个性化 → 基本 → 窗口大小，紧凑 820×520 / 标准 900×550 /
  宽屏 1080×650 / 超大 1280×760 / 自定义。选中即刻生效；手动拖过窗口边界再回来会自动落到
  「自定义」并显示当前实际尺寸。不超过屏幕工作区，也不低于窗口自身最小尺寸（820×470）
- **从 PCL2 导入后主题颜色不生效**：PCL2 用一个编号同时决定配色和纹理，这里拆成了两半——
  编号管纹理、`UiLauncherHue/Sat/Light/Delta` 管颜色。导入只搬了编号，于是纹理换了颜色还是旧的。
  现在编号变化时会按预设补齐参数，已经一致时什么都不做
- **「按版本覆盖」那两条黑条**：深色主题下没勾选「为这个版本单独设置」时，下面两个输入框会变成
  两条黑乎乎的长条。不是禁用态的问题，是输入框被判定成悬停/聚焦，底色变成了 `ColorBrush7`。
  现在外面包一层固定底色的 `Border`、输入框自己设成透明
- **更新按钮被裁成「wnload and ins」**：那颗按钮写死了 `Width="85"`，中文放得下、英文放不下。
  改成 `MinWidth` + 列 `Auto`，「再次检查」「查看更新日志」和可选更新卡片一起改了
- **基岩版页面被挤成一条缝**：左栏 `Width="Auto"` 而基岩版左栏没设宽度，一句长文案就能把左栏
  无限撑宽、把右边版本列表压到 230px。现在固定 260px，长文案改成换行 + 限高三行
- **自己点「结束游戏」被报成崩溃**：被 `TerminateProcess` 结束的进程退出码固定是 `-1`，
  而原来的判断是「非 0 就是崩了」。现在自己停的、任务管理器停的、杀软结束的都算「游戏已停止」，
  只有其它非零退出码才报异常。顺带修了「进程秒退时状态又被盖回游戏运行中」的竞态
- **繁中与英式英语补齐**：`zh-TW` / `en-GB` 缺的 59 个键全部补上（JarInJar 模组关系面板、
  皮肤披风名、区域限制提示、下载协议设置），四份语言文件现在完全对齐
- **设置 → Lunar 打不开**（1.5.2 起的回归）：两个按钮的处理函数写成了 `(object, RoutedEventArgs)`，
  但 PCL 自定义按钮的 `Click` 不是路由事件。这种错误编译期查不出来，顺手写了
  `tools/audit-xaml-events.py` 把全仓 `Click` 绑定和 code-behind 签名对了一遍

## 升级

直接覆盖，配置不变——**除非你是从 1.5.1 或更早升上来的**，那种情况数据目录换了名字，
需要重配一次并重新登录（见 ⑤）。

1.5.2～1.5.8 是快照版、1.5.9～1.5.12 是预览版，正式版通道之前停在 1.5.1 —— 这次会把正式版通道
一次性带到 1.6.0。

版本号写成 **1.6.0** 而不是 1.6：启动器的版本解析要求三段（`major.minor.patch`），
两段会让更新检查直接抛异常。

## 已知问题

- 发布文件已做代码签名（SHA-256 + DigiCert 时间戳）；证书为自签名，暂无商业信誉，
  个别安全软件首次运行时仍可能提示发布者信息
- 基岩版 GDK 安装包（`.msixvc`）解包依赖内置的内容密钥（CIK），正式版与预览版各一把，
  均已编入本构建；密钥若被官方轮换会失效，届时用环境变量覆盖即可，不必重新下载启动器
- Lunar 的本地 IPC 只实现了 `AuthService/RefreshAccount`（会话续期），好友列表、游戏内商店、
  聊天面板这些走 IPC 的功能仍然是空的。回空响应是安全的，游戏不会崩，只是对应界面没数据
- **PCL 没登录对应账号时续期会失败**，游戏内还是显示 Invalid session。想彻底解决，
  在主页面登录同一个微软账号即可
- Lunar 物料清单接口偶发 `SSL unexpected EOF`，重试几次通常能过
- 补齐原版依赖是按文件存在性判断的，不校验哈希；文件损坏（下了一半）仍要等 Genesis 自己
  发现并重下，那种情况依旧没有进度
- PCL2 原版（`setup.ini`）来源的导入只搬设置，**账号需要在账号页重新登录**——那一代的账号
  不是按新格式存的，硬转会写坏账号库。改过名的键也搬不过来，比如「上次选的版本」
  （PCL Lite 叫 `LaunchInstanceSelect`，PCL2 叫 `LaunchVersionSelect`），导入后要重新选一次
- 主页语言信封与 `lang:` 标签是 PCL Lite 扩展，原版 PCL 加载含这些内容的文件时
  会按普通 XAML 渲染（所有语言分支堆在一起）——属于预期的单向兼容
- UWP 安装需要开发者模式；系统策略禁用旁加载时只能手动到「设置 → 系统 → 开发者选项」打开
