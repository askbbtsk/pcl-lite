PCL Lite 1.6.1 正式版。

## ① 「窗口大小」下拉框装不下自己的文案

设置 → 个性化 → 基本 里那一行，选项写着「紧凑 820 × 520」「Extra large 1280 × 760」这种
带尺寸的长文案，但下拉框宽度写死成 `150`。控件的模板给文字只留了
`8.5 + 21.5` 的边距（右边那 21.5 是下拉箭头的），剩下一百来像素，
中英文都被裁掉一截、直接顶在箭头上。

现在放宽到 `200`。

宽度仍然是写死的，不能换成 `MinWidth`：`MyComboBox` 的模板里下拉面板是
`Width="{TemplateBinding Width}"`，不给 `Width` 会让展开后的列表塌成 0 宽。
这一点在 XAML 里留了注释，免得以后又有人「顺手优化」成 `MinWidth`。

## ② 版本号支持 hotfix 后缀了

以前版本后缀只有 `pre` / `snapshot` / `nightly` 三种，都是**正式版之前**的预发布。
所以「1.6.1 已经发了，但发现一处小问题」只能再占一个 1.6.2，版本号涨得比改动还快。

现在多了一档 `hotfix`，它打在同号正式版**之上**：

```
1.6.1-pre-1  <  1.6.1  <  1.6.1-hotfix-1  <  1.6.1-hotfix-2  <  1.6.2
```

- **所有后缀都带序号**：`pre-2`、`snapshot-3`、`hotfix-1`。没写序号的按 1 算，
  所以老的 `1.5.12-pre` 和 `1.5.12-pre-1` 等价，不用回头去改历史 tag
- **序号大的替换序号小的**：`hotfix-2` 覆盖 `hotfix-1`，同一套规则也管 pre / snapshot
- **hotfix 属于正式版通道**：稳定版通道的用户也能收到，否则热修复就白打了
- 下一版的正式版永远比上一版的 hotfix 新（`1.6.2 > 1.6.1-hotfix-9`）

这一条不是改个字符串就完事的。SemVer 的规则是「带后缀的版本一律低于同号正式版」，
直接用它比较会把 `1.6.1-hotfix-1` 判成比 `1.6.1` **旧**，于是装了这一版的用户
永远收不到热修复——正好是最需要它的时候。所以更新链路里的比较点全部换成了新的
`UpdateVersion`：GitHub 源挑版本、清单源的 `IsLatest`、多源同档内排序、
以及真正决定「要不要下载」的那道闸。

**这一版本身没有用到 hotfix**（它是正常的 1.6.1）。机制先放在那里，
以后真遇到「只改一两行」的时候再启用。

## 已知问题

- 发布文件已做代码签名（SHA-256 + DigiCert 时间戳）；证书为自签名，暂无商业信誉，
  个别安全软件首次运行时仍可能提示发布者信息
- 基岩版 GDK 安装包（`.msixvc`）解包依赖内置的内容密钥（CIK），正式版与预览版各一把，
  均已编入本构建；密钥若被官方轮换会失效，届时用环境变量覆盖即可，不必重新下载启动器
- Lunar 的本地 IPC 只实现了 `AuthService/RefreshAccount`（会话续期），好友列表、游戏内商店、
  聊天面板这些走 IPC 的功能仍然是空的。回空响应是安全的，游戏不会崩，只是对应界面没数据
- **PCL 没登录对应账号时续期会失败**，游戏内还是显示 Invalid session。想彻底解决，
  在主页面登录同一个微软账号即可
- Lunar 物料清单接口偶发 `SSL unexpected EOF`，重试几次通常能过
- 补齐原版依赖是按文件存在性判断的，不校验哈希；文件损坏（下了一半）仍要等 Genesis 自己
  发现并重下，那种情况依旧没有进度
- PCL2 原版（`setup.ini`）来源的导入只搬设置，**账号需要在账号页重新登录**
- 主页语言信封与 `lang:` 标签是 PCL Lite 扩展，原版 PCL 加载含这些内容的文件时
  会按普通 XAML 渲染（所有语言分支堆在一起）——属于预期的单向兼容
- UWP 安装需要开发者模式；系统策略禁用旁加载时只能手动到「设置 → 系统 → 开发者选项」打开
