PCL Lite 1.6.3 快照版 5（snapshot-5）。

> **这是快照版，不是正式版。** 把更新通道选成「快照尝鲜」就能收到；
> 「最新」也会收到，「稳定版」「预览体验」不会。
>
> 已经是 `1.6.3-snapshot-4` 的话，这次只有一个改动：好友与私聊的版本号容错。

## 问题：上一版的兜底值正好卡在服务端下限上

`snapshot-4` 把握手里上报的 `launcherVersion.semver` 改成读本机
`Lunar Client.exe` 的文件版本，读不到就回退到 `3.7.27`。

问题在于**这个回退是主路径，不是边缘分支**：PCL 的 Lunar 物料是自己从服务端下的，
根本不需要那个 Electron 壳，所以大多数 PCL 用户**没装官方启动器**，永远走回退值。

而 `3.7.27` 恰好贴着服务端的最低要求。Lunar 下一次抬下限，这批人就会集体连不上，
报的还是看不懂的关码 `1008 Unsupported launcher version`。

## 实测：服务端只校验下限，没有上限

逐个版本号打过一遍资产服务器握手（`wss://websocket.lunarclientprod.com/launcher-v3`）：

| 上报版本 | 结果 |
| --- | --- |
| 3.3.0 / 3.4.0 / 3.5.0 / 3.6.0 / 3.7.0 | 关码 1008 `Unsupported launcher version` |
| 3.7.20 / 3.7.25 / 3.7.26 / 3.7.27 | 放行 |
| 3.8.0 / 4.0.0 / 9.9.9 / 99.0.0 | 放行 |

也就是说：**只有下限，没有上限**。报一个远高于任何真实版本的号，必然满足下限。

另外认证服务（`authenticator.lunarclientprod.com`）**完全不看版本号** ——
`User-Agent` 里从 `3.3.0` 到 `99.0.0` 一律回 `encryptionRequest`。校验只发生在资产服务器
的握手阶段，所以被拒时拿到的 JWT 还能继续用，重试不必重新走 Mojang 的 session join。

## 改法：首选 + 被拒自动升级

```
首选：本机官方启动器版本（装了才有）→ 没有就用 4.0.0
被 1008 拒 → 自动改用 99.0.0 重连一次
两次都拒 → 报一句人话：「Lunar 服务端拒绝了当前启动器版本，通常是 Lunar 刚更新、
           把最低版本提高了，等 PCL 更新即可」
```

兜底值从 `3.7.27` 抬到 `4.0.0`，离当前下限（3.7.20 附近）留出了几十个补丁号的余量；
就算真被抬过去，还有第二跳兜着。

候选列表最多两项：每多试一次就要重连一次，列长了只会白白撞上服务端的连接限流。

## 验证

- 强制传 `3.7.0`（必然被拒的值）跑完整链路：自动升到 `99.0.0`，好友列表、会话列表、
  历史消息、发送消息全部正常
- 单测新增 3 条：版本号格式、候选列表以首选打头且不重复、退路必须明显高于真实版本
- `PCL.Core` 编译 0 错误；Lunar 相关单测 75 条全过

## 已知问题

- 好友/私聊依赖 Lunar 后端的私有协议，官方随时可能改字段；改了要重新逆向
- 服务端下限会随官方启动器更新继续往上抬；自动升级能自愈，但如果哪天连 `99.0.0`
  都被拒，说明协议本身变了，需要改代码
- 结束游戏是直接杀进程，不保证存档落盘（与官方行为一致）
- Lunar 物料清单接口偶发 `SSL unexpected EOF`，重试几次通常能过
- 补齐原版依赖是按文件存在性判断的，不校验哈希；文件损坏（下了一半）仍要等 Genesis 自己
  发现并重下，那种情况依旧没有进度
