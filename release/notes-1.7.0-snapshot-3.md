## 改了什么

### 一、登录方式不再跟账号名抢位置

上一版把登录方式拼成「账号名（设备代码）」，名字本来就长，加上后缀必然超宽：

```
Bed_Spacekiller_（设备…
```

方法名被省略号吃掉了，等于没标。现在挂在第二行的灰色信息里：

```
Bed_Spacekiller_
正版验证 · 设备代码
```

跟着「正版验证」一起灰，视觉上是一体的。账号详情页用的是同一份拼接逻辑，两处显示一致。

### 二、同一个号可以用多种方式各占一条档案

规则明确成一句话：**匹配键是「UUID + 登录方式」**。

| 场景 | 结果 |
| --- | --- |
| 同一个号，用设备码登一次、用令牌导入一次 | 两条档案，各自独立，互不覆盖 |
| 同一个号，用同一种方式再登一次 | 认定是续期，就地替换，档案位置和 ID 都不变，不新增条目 |

保留多条是有意的：不同方式的令牌寿命和续期能力完全不一样（Refresh Token 能一直续、Minecraft 令牌 24 小时就废），混成一条反而说不清自己手上这条还能用多久。

**顺带修了个会让它失效的 bug**：续期回来的结果里 `LoginMethod` 是空的，旧代码会把它归一化成 `device` 再去匹配 —— 一个 Cookie 档案续期时找不到自己，凭空多出一条 `device` 档案。现在结果没带登录方式就退回按 UUID 找第一条，宁可命中一个已有槽位，也不新增重复项。

## 已知问题

- **Cookie 登录那条路仍然没在真实登录态下验证过**。代码路径是通的（授权码 + `prompt=none`），
  但手上没有一份真实可用的 Cookie 去实测，可能会回 `login_required`。真遇到了就先用
  Refresh Token 或设备码，别在 Cookie 上耗时间
- 令牌导入的账号 24 小时后必须重新导入，这是微软定的，没有绕法
