PCL Lite 1.7.0-snapshot-4。

> 快照版，只有选了「快照」或更激进通道的用户会收到。稳定版通道请继续用 1.6.4-hotfix-5。

## 改了什么

### 一、Discord 应用 ID 不再可改

设置里那个「应用 ID」输入框删了，改成本项目自己的应用写死在代码里。

那个框除了让人填错之外没有任何用处：填成别人的应用，状态卡片上显示的就是别人的应用名和图标；填错一个字符就整条链路连不上，而用户根本无从判断是自己填错了还是 Discord 没开。现在不给改，也就没有「填错了」这种状态。

老配置里残留的那一项会被当作未知键忽略，不用手动清理。

### 二、游玩时长不再莫名归零

这一版把「时长卡住 / 从头开始」的几个独立原因都修了：

| 原因 | 表现 | 修法 |
| --- | --- | --- |
| 取内存失败被当成游戏没在跑 | 时长忽然归零 | 只有「进程已退出」才判定没在运行，取内存失败只放弃那一项数据 |
| 单次读不到快照就清空起点 | 时长从头开始 | 连续 15 秒都读不到才算真的退出 |
| 起点是「第一次发现游戏在跑的时刻」 | 一旦被清就永远对不上 | 改用游戏进程自己的启动时间，怎么重算都是同一个值 |
| 管道报「已连接」其实对端已经没了 | 状态停在最后一帧不动 | 超过 90 秒没成功发出去过任何东西就强制重连 |
| 被 Discord 限流一次就断开 30 秒 | 状态空白一阵又回来 | 限流只记错误不断连接；重连间隔也从 30 秒降到 15 秒 |

### 三、启动器公告真的能用了

以前这条链路是死的：公告走 GitHub Releases，而代码里直接返回空列表，所以「启动器公告」那个设置项选哪一档都没区别。

现在公告来自清单仓库根目录的一个独立文件：

```
https://raw.githubusercontent.com/bedkillerspacex-boop/Pcl-Lite-service/main/notice.json
```

- **改这个文件就等于发一条公告**，不用发版，客户端每次启动拉一次
- 走的是和更新清单同一套多通道抢答，raw 拉不到会自动换 jsDelivr 或反代
- 拉不到、文件不存在、JSON 写坏，一律当作没有公告，不影响启动、不弹错误
- 公告用 `id` 去重，看过的人不会再被弹第二次
- `important: true` 的条目，「仅重要」档的用户也会收到（这个档位以前没有实际过滤逻辑，现在有了）

字段说明直接写在文件里的 `_字段说明` 那一项。

## 已知问题

- **Cookie 登录那条路仍然没在真实登录态下验证过**。代码路径是通的（授权码 + `prompt=none`），
  但手上没有一份真实可用的 Cookie 去实测，可能会回 `login_required`。真遇到了就先用
  Refresh Token 或设备码，别在 Cookie 上耗时间
- 令牌导入的账号 24 小时后必须重新导入，这是微软定的，没有绕法
- 公告文件刚建好，`content` 是空的，所以这一版不会弹任何公告
