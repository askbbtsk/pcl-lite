## 改了什么

只有一处：**公告不再走 jsDelivr**。

上一版刚把公告改成从清单仓库的 `notice.json` 下发，说「改文件即生效」。实际测的时候发现不成立：

- 公告是多通道并发抢答，谁先回用谁
- jsDelivr 对 GitHub 路径默认缓存 **12 小时**
- 于是它命中缓存时反而最快，把**旧内容**顶上来，新公告看起来没生效

现在公告只走三个准实时通道：GitHub Contents API、raw 直连、以及下载用的那几个反代。jsDelivr 跳过。

清单文件（`update.json` / `updatev2.json`）不受影响 —— 那两个只在仓库搬家时才改，缓存反而是好事，行为完全不变。

## 顺带一提

这一版开始，启动器会弹第一条公告了（「欢迎使用 PCL Lite」）。内容是放在 `notice.json` 里的，不发版也能改。

不想看公告的话：设置 → 启动器 → 杂项 → 「启动器公告」，选「仅重要」或「关闭」。

## 已知问题

- **Cookie 登录那条路仍然没在真实登录态下验证过**。代码路径是通的（授权码 + `prompt=none`），
  但手上没有一份真实可用的 Cookie 去实测，可能会回 `login_required`。真遇到了就先用
  Refresh Token 或设备码，别在 Cookie 上耗时间
- 令牌导入的账号 24 小时后必须重新导入，这是微软定的，没有绕法
- 反代（ghproxy 之类）如果自己带缓存，理论上也可能返回旧公告。遇到「改了没生效」先等一两分钟再试
