# PCL Lite 1.7.5-pre-2

本次预览版包含 pre-1 的全部功能，修复部分模组无法解析时，整个实例被误报为索引失败的问题。

## 索引按文件容错

- 不支持、损坏、无权限、扫描期间变化或无法完整解析的模组只跳过自身，其他文件继续建立并保存索引，不再把整个实例判为失败。
- 已保存的正常条目保持可用；同目录、同解析环境的其他实例也能复用部分索引，不因一个异常文件放弃整组缓存。
- 单实例创建和全实例创建均集中列出跳过文件的完整路径及原因，不修改或删除这些模组。无法解析的关系仍保持未完成，不伪装成全部成功。
- 全实例汇总分别显示已保存索引的实例、含跳过项的实例、跳过模组数，以及目录或保存失败数。
- 每个顶层模组独立计算递归解压预算，避免一个异常归档耗尽预算，连带跳过后面的正常模组；保留单文件深度、节点、条目大小及解压总量限制。
- 下载后的索引即使包含跳过项，也会刷新仍匹配当前实例和列表代数的页面，展示已保存的正常结果。
- 单文件读取或解析异常不终止整批任务；文件排序时发生删除或权限变化也不会拖垮其他文件。取消仍保存已完成条目，缓存保存失败单独处理。

## 保留行为

- 设置 → 游戏管理的“立刻创建索引”仍处理 PCL 已发现的全部 Minecraft 目录及有效实例，包括未选中和隐藏实例。
- 待机和普通浏览不自动补建；下载、更新模组后仍自动更新相关索引。保留“不再提示”、受控并行、手动任务优先及取消恢复。
- 不切换主页当前实例或 Minecraft 根目录，不改变用户的模组、配置和存档。

## 验证与发布

- 功能提交已通过 GitHub CI 的 920 项测试、x64 / ARM64 构建、TestAll 构建及源码契约检查；发布版本提交另行执行 CI。
- 新增回归覆盖日志中“48 个文件、3 个未完成”等批次，以及损坏归档、权限失败、文件删除、取消保存、保存失败、并发上限和全部文件不支持等场景。
- 沿用发布流程注入 OAuth client ID，分别生成并验证两种架构的 Sigstore 签名，发布页附带 `.sigstore.json` 文件。
- 真实用户模组集和 GUI 全流程仍需验收；不把测试通过等同于所有交互已实测。

## 建议测试

1. 在原来含有无法解析模组的实例上重新建立索引，确认正常模组索引保存，异常项显示具体文件及原因，实例不再整体报失败。
2. 对照全实例汇总，确认“跳过文件”和“目录或保存失败”分别统计；共享 mods 目录中的正常索引仍能复用。
3. 取消创建后再次运行，检查已完成条目可复用，原模组文件没有被修改或删除。
