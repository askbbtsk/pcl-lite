# PCL Lite 1.7.5-snapshot-3-hotfix-1

本次为 snapshot-3 的后续修复预览版，包含原版本的全部功能。

## 修改实例

- 将“跨加载器迁移”入口改为“修改加载器”，新增独立选择目标加载器的入口。当前 Fabric 不再锁住 Forge/NeoForge 选择；改游戏版本时清除旧版本的待安装构建，避免带入不兼容选择。
- 卡片和页面底部按钮共用当前实例修改流程。更换 MC 版本或加载器种类时，先在临时目录安装并验证，再将确认的核心、Java 偏好和模组变更通过同一事务提交；不整目录替换配置和存档。
- 操作前明确要求自行完整备份，再弹出强制等待 5 秒的二次确认。使用原生 PCL 弹窗，等待从实际显示开始，提前点击或按 Enter 均不能绕过，取消立即有效。
- 更换版本或加载器时询问是否迁移现有模组。选择迁移还需等待 3 秒再次确认，并逐项选择可靠的目标构建。被替换的原模组保留为禁用文件，原禁用状态保持；未知项、冲突和无法迁移的内容保留并报告。
- 针对目标环境自动选择 Java，仅调整对应偏好并保留其他设置。提交及中断恢复后清除旧实例对象的版本/加载器缓存，避免显示或启动仍沿用旧信息。

## 索引性能与文件占用

- 当前实例优先建立索引；切换/刷新时取消过期队列，迟到任务和回调不能覆盖当前实例结果。
- 内嵌模组递归改为受控并行，跨批次最多 3 个实际任务，低核心机器自动减少。无内嵌声明的普通 JAR 直接缓存空关系，不再全部重复扫描。
- 缓存按实例分锁，只刷新当前实例，减少其他实例压缩落盘对前台的阻塞。
- 修复模组哈希计算阻止删除、改名和外部编辑的问题。扫描允许共享删除，文件变化或消失时拒绝旧摘要，不将变化中的结果缓存。
- “模组仍在解析”选择继续后使用原生可取消后台进度弹窗，不再在 UI 线程递归补解析；取消或切换实例不继续原删除/启停动作。

## 验证与测试范围

- 新增倒计时、原地事务、INI 定点修改、当前批次优先调度及真实文件句柄删除/编辑回归测试；通过发布提交的 GitHub CI 后发布 x64 / ARM64。
- 继续由发布流程注入 OAuth client ID，生成并验证 Sigstore 签名；两种架构均附 `.sigstore.json`。
- 修复快照热修复后缀的通道与排序，保持本版属于快照版，后续 snapshot-4 和正式版仍可正常升级。
- 未在本机运行真实 MC/Forge 下载或 GUI 全流程；这些场景仍需用户验收，不把 CI 等同于全部交互实测。

## 建议按顺序测试

1. 先自行备份测试实例。在“修改实例”选择 Fabric → Forge/NeoForge，确认目标版本列表可打开。
2. 观察备份二次确认：未满 5 秒点击或按 Enter 无效，取消不改文件。
3. 修改 MC 版本，选择迁移模组；未满 3 秒不能确认。检查原位版本更新、可迁移模组和无法迁移报告。
4. 检查替换后的旧模组仍以禁用文件保留，原禁用模组未启用，配置及存档未被覆盖；也测试“不迁移，保留原样”。
5. 打开大型实例 A 后迅速切换 B，确认 B 优先索引；在测试文件上执行删除/改名，不应再被后台索引占用。
6. 索引未完成时操作删除，点击继续观察后台进度并取消，确认界面能响应且未继续删除。最后启动目标游戏，确认显示与实际加载器一致。
