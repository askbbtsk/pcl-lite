# PCL Lite 1.7.5-snapshot-4

本次预览版包含 snapshot-3-hotfix-1 的全部功能，集中修复修改实例时的模组依赖规划、重复下载及任务进度显示。

## 模组迁移与依赖

- 在安装目标环境和下载模组前，对全部已选目标模组统一检查必需依赖。迁移列表中已有且满足要求的目标构建直接用于满足依赖，不再因列表顺序重复查询、重复提示或重复下载。
- 多个模组共用的依赖统一规划一次；保留精确的项目、文件及固定版本要求，使用原始游戏版本元数据判断兼容性。
- “修改加载器”卡片新增原生 PCL 选择框“自动下载全部必需依赖”，默认关闭。勾选后，本次操作自动下载能够解析的必需依赖；未勾选时统一确认一次。可选依赖不会自动加入，无法解析或存在冲突的项目仍会报告。
- 必需依赖在目标加载器下不可用时，不再下载到最后才以一个项目 ID 报错。预检会排除无法完整迁移的候选，保留源模组，并说明原因，由用户决定是否继续处理其他可迁移项目。保留的旧模组仍可能不兼容目标环境，请查看报告。
- 原本禁用的模组保持禁用，不会被当作启用依赖，也不会意外激活它们的依赖。目标文件名冲突、固定版本冲突及重复目标文件会提前报告。
- 目标模组及依赖通过现有 PCL 批量下载任务处理，沿用授权、代理、速度显示和取消机制。提交前复核暂存文件、实际模组声明、依赖、冲突、运行库及 Java。

## 原生任务进度

- 修改实例时自动打开现有任务管理页面，显示识别目标构建、预检依赖、安装目标、批量下载、验证和提交六个阶段。
- 查询阶段显示当前项目和计数，下载阶段显示文件完成数量；总进度按阶段权重推进，不再随每个子文件重复从 0 开始。
- 修复原任务分组隐藏导致迁移进度不可见的问题；即使总百分比未改变，任务卡片的阶段和说明也会刷新。
- 只有持久化事务完成后才显示 100%；过期及乱序回调不能倒退进度或覆盖后续阶段。

## 修改确认

- 修复仅修改加载器时出现“Minecraft 26.2 修改为 26.2”的误导文案。两次迁移确认均显示实际变更类型、当前环境及目标环境，包括游戏版本、加载器和构建版本。
- 保留操作前备份提示、强制 5 秒备份二次确认及迁移模组的 3 秒二次确认；简体中文、繁体中文和英语同步更新。

## 验证范围

- 功能提交已通过 GitHub CI：877 项测试，以及 x64 / ARM64 构建、TestAll 构建和源码契约检查。发布版本提交再次通过 CI 后发布。
- 新增覆盖共享依赖、迁移列表先后顺序、固定文件版本、禁用模组、依赖环和深度限制、文件名大小写冲突、查询异常、取消及并发进度回调等回归测试。
- 覆盖多加载器模组声明了仅支持 Fabric 的必需依赖这一失败场景；不会按名称擅自替换为其他项目或忽略必需依赖。
- 发布流程注入 OAuth client ID，并为 x64 / ARM64 分别生成、验证和附带 Sigstore 签名文件。
- 未在本机完成真实游戏启动、全程联网迁移及 GUI 交互验收；CI 通过不代表这些场景已实测。

## 建议测试

1. 自行备份测试实例，再修改游戏版本或加载器，确认提示准确显示来源和目标环境。
2. 选中一个模组及其依赖一起迁移，确认依赖不重复提示、不重复下载；再测试多个模组共用一个依赖。
3. 分别关闭、开启“自动下载全部必需依赖”，检查统一确认和自动补齐行为；无法满足的依赖应有明确报告。
4. 在任务管理页检查六阶段进度、下载速度和取消响应。取消后源配置、存档及未提交的模组应保持原样。
5. 检查禁用模组仍禁用，替换的旧模组仍保留为禁用文件，最后启动目标实例验证实际加载器及模组。
