# PCL Lite 1.7.5-snapshot-5

本次预览版包含 snapshot-4 的全部功能，调整模组索引的创建方式，并优化并发读取和缓存写入。

## 按需建立索引

- 设置 → 游戏管理新增原生 PCL“立刻创建索引”按钮，高 42px，针对主页当前选择的实例创建索引。创建过程可取消，已完成条目会保存。
- 待机和普通浏览不再自动补建缺失的内嵌模组关系索引。打开模组页面发现索引缺失时，提供“立刻创建索引 / 稍后 / 不再提示”；同一会话每个实例只提示一次。
- “不再提示”持久保存，并可在游戏管理设置中重新开启；对应选择框高 32px。
- 下载或更新模组后仍会自动更新索引。合并短时间内完成的同目录下载，只处理相关文件；尚未打开过的实例保留下载请求，下次打开模组页时处理。兼容旧 Forge 的版本子目录。

## 并发与响应

- 顶层模组元数据和 SHA-1 预热改为受控并行；显式索引按 CPU 与可用物理内存共同限制为 1–8 个 worker，大文件优先。保留递归层数、节点和解压总量限制。
- 手动创建优先于下载触发的后台构建：后台协作取消并保存完成项，手动操作结束后使用已有缓存继续处理。多个构建统一协调，避免无上限同时扫描。
- 缓存直接流式写入压缩临时文件后替换，使用 Fastest 压缩，减少内存复制和压缩耗时，沿用现有缓存格式。
- 后台索引成功后刷新仍对应当前实例和当前列表代数的页面，避免索引已经完成但界面仍保留“待解析”状态。
- 扫描期间删除、改名、改写或无法读取个别文件时，跳过其摘要查询并记录原因，其余文件继续显示。保留允许文件删除的读取共享方式。

## 验证范围

- GitHub CI 验证核心测试、TestAll 插件、源码契约及 x64 / ARM64 构建；新增提示去重、下载请求合并、并发上限、前台抢占和取消恢复等测试。
- 通过现有发布流程注入 OAuth client ID，并为两种架构生成、验证 Sigstore 签名。
- 尚未实测用户完整模组集的冷/热缓存加速倍数，也未完成真实游戏和 GUI 全流程验收；不把 CI 等同于所有交互已验证。

## 建议测试

1. 打开尚未索引的测试实例，选择“稍后”，确认待机不再开始补建；再测试“不再提示”及重启后的记忆。
2. 在设置 → 游戏管理点击“立刻创建索引”，观察处理数量与取消；再次创建应复用已完成缓存。
3. 下载、更新几个模组，确认自动更新索引仍有效，当前页面不一直保留旧的“待解析”状态。
4. 另一实例正在后台索引时手动创建当前实例索引，确认手动任务优先；完成后后台继续。
5. 在副本上扫描时删除或改名一个模组，检查其余列表可用且没有后台句柄阻止操作。
