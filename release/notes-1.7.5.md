# PCL Lite 1.7.5 正式版

本说明按 **1.7.2 正式版（含随后 hotfix-1、hotfix-2）→ 1.7.5 正式版**汇总最终保留的改动。期间 nightly、snapshot、pre、early 为开发与验收版本；下文描述的是当前正式版行为，已撤回的自动备份和内部回收站不计作现有功能。

## 液态玻璃与个性化

- **独立液态玻璃开关**：在“设置 → 个性化”提供“液态玻璃 · LiquidGlass”，默认关闭，不归入高级材质。开启前弹出性能确认，无倒计时；取消保持关闭，确认后在开关下展开参数。
- **四档实际参数**：低消耗、均衡、高画质、极致分别调整模糊、色散、高光和按压动效，默认上限为 30、60、90、120 FPS。预设框与选项最小高度 38 DIP，开关高 32 DIP。
- **自由设置效果帧率**：滑块支持 30–240 FPS，最右端为不限制。上限用于桌面回读/上传和玻璃按压动画，拖动、缩放窗口也受限制；不影响 Minecraft 自身帧率。
- **默认截图兼容**：默认折射启动器背景。实时桌面采样另行开启，并明确确认采集开销和截图限制；采样使用 Windows 截图排除标志，开启时窗口仍存在，但不会出现在截图或录屏中。关闭实时采样恢复截图可见性。
- **背景由用户控制**：开启实时桌面折射不再自动隐藏壁纸或暂停视频。需要隐藏背景时手动降低“不透明度”；玻璃开启时它只调整背景颜色层和壁纸层，玻璃、文字和桌面折射源保持独立，不再一起变淡。
- **关闭后恢复原设置**：退出玻璃模式后恢复原有整窗不透明度及高级材质配置，不改写用户保存的透明度数值。
- **夜间文字修复**：侧栏标题、路径和启动说明在关闭玻璃后重新使用动态主题颜色，修复 Lunar 等页面小字回落为黑色、暗色背景下无法阅读的问题。
- **采样恢复**：显示器变化触发重建，旧帧及旧错误回调不能污染新会话；重试耗尽时退役全部采集，避免画面失效却持续排除截图。恢复截图状态暂时失败时进行有上限的重试，窗口关闭后停止。
- **隐藏插件市场**：“个性化 → 功能隐藏 → 主页面”新增插件市场选项，立即隐藏顶部和折叠区域的入口，选择跨启动保存；取消恢复，不停用或卸载插件，临时显示隐藏功能仍可使用。
- 玻璃实现以 `LiquidGlassCore` 为核心，替换旧的未接线资源，源码和资源采用 LiquidGlass 文件名；设置标题不再显示 Core。原 PR 作者提交、兼容入口和来源声明保留。

## 游戏启动计数

- 总启动计数不再只覆盖普通 Java 启动，同时接入基岩版和 Lunar 的成功启动路径。
- 重复通知不会给同一次启动重复计数，失败和取消不计入；原有累计值保留，不根据旧日志补算历史启动。
- “工具 → 查看启动计数”继续读取同一个总数，Java 实例自己的启动次数仍单独保留。

## 修改现有实例：游戏版本、加载器和模组

- **加载器可以重新选择**：“修改加载器”不再因当前实例为 Fabric 就锁死 Forge/NeoForge 的候选；修改 Minecraft 版本时清除旧版本的待安装构建，避免沿用不兼容选择。
- **先暂存验证，再修改原实例**：使用现有安装器完成目标环境，校验生成的版本、运行库、Java、实际模组声明及必要依赖后，再提交选定核心和模组文件。配置、存档及未选择的资源不被整目录替换。
- **备份确认**：修改前明确要求用户自行备份，并有可取消的 5 秒二次确认。选择迁移模组时另有 3 秒确认，提前点击或按 Enter 不会绕过等待。
- **提示显示真实变更**：确认窗口显示当前和目标 Minecraft、加载器及构建版本；仅换加载器时不再用“26.2 修改为 26.2”误导用户。
- **跨版本、跨加载器查询**：对能可靠识别来源的模组，在同一项目下查找明确支持目标游戏版本和加载器的构建。不靠同名猜测另一个项目是等价替代。
- **未知或不兼容项保留**：无法可靠迁移的来源不删除，列出原因，由用户确认是否继续其他可处理项。选择不迁移时保留现有模组，明确说明它们可能不兼容目标环境。
- **原文件和禁用状态**：替换后的旧启用模组保留为禁用文件；原来禁用的模组迁移后仍保持禁用，不因下载默认文件名意外启用。候选模组默认勾选时可立即点击“继续”，无需先切换选项。
- **Java 与配置**：目标环境沿用原生 Java 选择约束重新判断，不盲目继承来源环境；只定点修改确认过的 Java 偏好，保留 INI 的其他字段、编码和换行。
- **系统 Temp 暂存**：`.pcl-modify-*` 不再直接出现在用户 `versions` 中，而放入系统 Temp 的任务工作区；原版下载、忽略标记和合并输出统一使用明确的目标路径。
- **自动清理**：安装/下载 worker 退出后，成功、失败和取消均清理拥有归属标记的暂存工作区。启动器下次启动重试清理已解锁残留；活跃租约、不明归属和链接不盲删。旧版本遗留在用户版本目录的未知内容不按名称自动删除。
- **事务恢复**：核心文件、模组和元数据纳入写前日志，完成后写独立提交标记；中断后识别已登记的未完成操作。恢复不会继续旧下载，也不覆盖事务外新增的用户修改。
- 提交或恢复后刷新当前实例的版本 JSON 和加载器缓存，避免文件已变、显示或下次启动仍沿用旧对象。

## 模组依赖预检与任务进度

- **整个选择集合统一预检**：在安装目标和下载前检查全部选中模组的必需依赖，保留精确项目、文件及固定版本要求，使用未裁剪的游戏版本声明判断兼容性。
- **不重复下载已选依赖**：同一构建已在迁移列表中即可满足依赖，无论列表先后；多个模组共用的前置统一查询和规划一次。
- **提前发现冲突**：固定版本冲突、目标文件名及大小写碰撞、依赖环、深度限制、非法文件名/摘要、无兼容构建和平台查询失败均在提交前报告。
- **自动下载全部必需依赖**：修改加载器卡片提供独立选项，默认不勾选。勾选后授权本次批量补齐可靠匹配的必需依赖；未勾选时统一确认一次，可选依赖不自动加入。
- Fabric-only 前置不会在 NeoForge 下被强行忽略或替换为名字相似项目。无法满足依赖的候选从本次替换中排除，原文件保留，并提示是否继续其他项。
- **原生任务管理**：修改任务自动进入 PCL 任务页，展示识别模组、依赖预检、安装目标、批量下载、验证和提交六阶段。查询显示当前项目/文件计数，下载沿用授权、代理、速度和取消。
- 总进度按阶段权重推进，不随每个子文件反复归零；事务提交完成前不显示最终 100%，过期回调不能倒退或覆盖后续阶段。

## 模组索引：手动全实例、下载后自动、单文件容错

- **不在待机补建**：普通浏览只读已有关系缓存。打开模组页面遇到缺索引时提供“立刻创建索引 / 稍后 / 不再提示”；同一会话按实例去重，“不再提示”持久保存，可在设置重新开启。
- **全部已发现实例**：“设置 → 游戏管理”的 42px 原生按钮为 PCL 已发现的全部 Minecraft 根目录及有效实例建索引，包含隐藏、未选中实例，不切换主页选择。
- **总体进度**：显示已处理实例、总实例、当前实例及处理文件数；目录或实例发现失败后继续其他项，最终集中报告。取消保留完成项。
- **正确处理多目录**：未隔离实例使用它实际所属的根目录；继承版本 JSON 也从该实例自己的 versions 目录读取，避免串到当前选中的另一 Minecraft 目录。
- **共享目录复用**：只有模组目录、加载器、游戏版本及旧 Forge 子目录规则一致时复用扫描，仍为各实例保存独立索引。
- **受控并行**：顶层元数据与 SHA-1 预热并行；递归索引根据 CPU 和可用内存限制为 1–8 个 worker，手动请求优先，后台被抢占后使用完成缓存重试。
- **下载仍自动更新**：下载和更新模组后保留自动索引，合并短时间内同目录的完成通知，只处理相关文件；支持旧 Forge 的合法版本子目录。
- **不因坏文件放弃整批**：不支持、损坏、无权限、扫描中变化或解析不完整的文件只跳过自身；其他索引继续保存、共享和使用。报告区分已保存实例、含跳过项实例、跳过文件、目录/保存失败。
- **列出具体文件**：跳过项集中显示完整路径和原因，不修改或删除来源；未知关系不伪装为解析成功。每个顶层模组有独立解压预算，异常归档不会耗尽后续正常文件的额度。
- **扫描不占住删除**：普通索引和哈希读取允许共享删除、改名及外部编辑；文件指纹变化时拒绝旧结果。立即失败的待处理哈希任务不会永久残留，原路径文件恢复后可重新计算。
- 缓存流式压缩到临时文件后替换，减少内存复制与压缩耗时；下载索引完成后只刷新仍匹配的当前实例/列表代次。

## 整合包制作与导入

- **附带启动器三选一**：默认不附带；可附带当前运行的完整 PCL Lite，或导出时在线下载 PCL Light。不再把原版 PCL 当成整合包附带启动器，也不把 Light 预先内嵌进 Lite。
- **Light 架构与来源**：从 `bedkillerspacex-boop/Pcl-Light` 的正式 Release 选择 x64/ARM64 EXE，一次导出固定 Release 和资产；EXE 与摘要文件均可走现有代理回退。
- **强制内容校验**：验证 Release 资产 SHA-256，缺少摘要时使用同一 Release 的 `SHA256SUMS.txt`；仍无法校验则停止导出。失败或取消不覆盖已有最终包。
- 附带启动器时，外层 ZIP 包含所选的单个启动器和 `modpack.mrpack`；完整 Lite 与 Light 不同时打包。
- **实例内 Java**：可选择打包所选实例内部已有的 Java，校验结构和路径，不下载或复制电脑其他位置的运行时；Lite 使用实例相对路径，Light 适配其运行时路径语义。
- **安装后隔离策略**：导出时选择安装后开启/关闭隔离，默认开启，只影响导出结果，不修改作者正在使用的实例。导入明确声明关闭隔离的包时按共享目录布局处理，不覆盖同路径不同内容文件。
- **配置兼容**：旧 `IncludeLauncher` 继续解释为完整 Lite；兼容已支持的 LF Java 和隔离导出字段。LF 精简模式不启用，相关未应用项明确提示。
- 保留文件分类、规则过滤、追加文件、Modrinth 上传模式和配置导入导出。上传模式不附带启动器，也不直接捆绑不允许分发的外部资源。
- 来源记录、增强缓存、集合索引、恢复资料、临时任务和凭据缓存不混入导出；最终包先写临时文件，完成后替换，失败不留下目标半成品。

## 整合包更新、体检和 Prism

- **在线与本地文件更新**：按已记录的 Modrinth/CurseForge 来源更新，或选择本地 ZIP/MRPACK 更新当前实例；先预览作者新增、修改、删除及玩家改动。
- **个人修改优先**：默认保留个人新增、修改、禁用及删除状态；同路径冲突明确报告，不把“文件不在作者清单”直接当作可以删除的理由。
- 游戏文件和来源基线一起登记到持久化事务，中断恢复保护已登记原内容及并发外部修改；不依赖两个 JSON 分别移动就假设联合原子性。
- **实例体检**：依据现有有效版本 JSON 和运行库声明检查缺失、损坏、未验证及路径问题。辅助 `resolved.json` 缺失或损坏可重建，不取代当前用户文件作为真相源。
- **补缺与维护**：体检默认只补缺失库，不自动覆盖已有损坏文件；提供实际文件差异对比、辅助缓存清理及重复增强身份报告。清理保留声明、个人记忆和事务恢复资料。
- **Prism 只读导入**：从 Prism 实例目录读取已适配的原版/Fabric/Forge/NeoForge 环境，调用 Lite 原安装器生成独立目标。保留三个独立组件标志和受支持补丁顺序，不改 Prism 来源。
- 未支持的启用组件、Quilt 及无法无损映射的自定义操作会明确拒绝或报告，不宣称任意 Prism 实例都能完整导入。

## 本地资源、备份与个人设置

- **模组集合**：记录多个位置的实际文件索引，不移动原文件。可确认的路径别名合并；缺失、链接和无法确认的记录保留状态。
- 集合复制使用暂存与哈希校验；相同内容可复用，同名不同内容不覆盖，失败逐项报告，禁用后缀保持。不跟随链接去导入来源。
- **Windows 回收站**：资源、截图、存档、数据包及实例删除统一按全局选项处理，默认进入 Windows 回收站，可选直接删除；不再维护另一套内部资源回收站。
- **只保留手动备份**：世界手动备份、环境还原点的查看、比较、恢复和删除仍可用。环境恢复保留 saves，删除还原点按明确提示处理。自动世界备份、自动还原点和内部回收站已移除。
- **测试副本**：显式复制测试实例时为增强记录生成新身份，不继承旧的派生缓存和未完成事务；普通外部复制出现重复身份时只报告，不擅自判断哪个是原件。
- **个人设置同步**：跨实例游戏设置可按类别选择，默认关闭；按实例键鼠设置记忆按现有独立开关处理，首次不覆盖，冲突先预览，可靠正常退出才采集。
- 最近世界记录绑定启动会话，支持正常/异常结束及中断会话整理；存档页面保留快捷启动。欢迎页没有强行加入“继续上次世界”卡片。

## 主页、Lunar、更新与维护

- **欢迎页和性能页分开**：恢复欢迎页，另提供性能状态主页预设。CPU/内存状态在本地计算，比例条随实际宽度变化，离开页面停止采样，日志区域由外层滚动。
- **Lunar 会话隔离**：退出、停止、输出和 IPC 等延迟回调按会话归属校验，旧游戏的结束通知不会盖掉替换后的游戏，也不会中途把仍运行的新会话报成结束。
- **服务更新清单只保留 v2**：服务仓库删除 v1 `update.json`；启动器 v2 缺失、超时、返回 HTML 或解析失败时不再请求 v1，旧单指针填入 v2 也会拒绝。
- 发布/镜像仓库根目录的 `update.json` 仍作为身份标记保留。v2 多通道、权重分档、镜像校验、直接 GitHub Releases 后备源、下载摘要和签名验证保持。
- 修正快照热修复后缀的通道与排序，后续快照和正式版可按版本顺序识别。
- **30 个遗留大文件拆分**：按下载/安装、资源解析、启动、窗口、Lunar、Bedrock、插件与 Mixin 等职责整理；提取 `MessageNoticeCore` 等模块，保留旧公开入口、嵌套类型身份及初始化顺序。
- CI 增加四种配置的源码契约、超长文件和共享 Java 规则检查；TestAll 示例插件增加提取模块探针。插件 SDK 的既有接口在本周期延续，并不把此前已发布的接口重复列作新增。
- 保留 JetBrains 致谢，特别感谢 IntelliJ IDEA；包含主页和玻璃相关 PR 作者的贡献与来源声明。

## 验证范围与升级提示

- GitHub CI 执行全量核心测试、玻璃 WPF/采集协调测试、TestAll、源码契约以及 x64 / ARM64 主程序构建。
- 发布工作流注入 OAuth client ID，为两种架构分别生成并验证 Sigstore 签名；EXE 和对应 `.sigstore.json` 一起发布。

- 修改或恢复重要实例前请自行备份。未知模组和不兼容构建保留并报告，不自动证明其可运行。
